01 / SYSTEM MAP全体構成図

Cloudflareは管理・音声ジョブ・公開配信を担当し、このPCは画像生成と動画化を担当します。Google Driveは元の原稿と成果物、R2は公開用の動画を保存します。

管理API・配信・クラウド処理Driveとのデータ入出力PC上の生成・自動公開

スマートフォンでは図を左右にスクロールできます。矢印は主な依頼・データ経路を示します。

クラウドに残るもの

管理画面、音声ジョブ、Driveの成果物、R2の公開動画。公開後の動画はPCが停止しても配信できます。

PCが必要なもの

CLI画像生成、FFmpegによる動画化、R2の確認と初回セットアップ、新規動画のアップロード。

原稿作成は別の処理

このアプリはDriveの既存原稿を入力にします。YouTubeから原稿を作る処理と、YouTubeへの投稿は含みません。

03 / AUTOMATION自動実行の時間と実行場所

処理間隔・上限実行場所PC停止時
定期音声生成毎時00分・最大4件を登録Cloudflare Cron＋Durable Object本番側で継続
漫画・図解生成毎時15分・最大1件このPCのsystemd＋Codex CLI生成は停止
動画公開サイクル毎時00・15・30・45分・最大2件このPCのsystemd＋FFmpeg新規動画の作成・公開は停止
公開済み動画の閲覧視聴者がアクセスしたときCloudflare Worker＋R2引き続き閲覧可能
1回の処理が長引いても、同じPCのロックで二重起動を防ぎます。ユーザーサービスが動作し、CLI・Wranglerの認証が有効であることが必要です。ログアウト後のサービス稼働はPCの設定に依存します。

04 / HOW TO USE画面の使い方

管理画面で成果物を確認する

  1. 管理画面に管理者パスワードでログインします。
  2. 案件カードを開き、漫画・タイトル、原稿・音声、元動画情報を確認します。
  3. 「最新状態に更新」は表示を再取得します。「カタログ同期」はDriveの実ファイルを再確認して一覧を更新します。
  4. 音声の手動実行は最大4件をキューへ登録します。「実行履歴」で成功・失敗・再試行予定を確認できます。

動画を連続して見る

  1. 動画ライブラリでタイトルを検索し、動画を選びます。
  2. 最初の動画は再生ボタンを押します。ブラウザが自動再生を制限する場合も、再生ボタンから開始できます。
  3. 「連続再生」が有効なら、終了後に次の動画へ進みます。「最後から先頭へ」で繰り返しも可能です。
  4. 「再生速度」で0.5〜2倍の7段階を選べます。速度は次の動画へ引き継ぎ、ブラウザ保存が使える場合は再読み込み後も保持します。
  5. 「この動画のリンクをコピー」で個別の共有URLを取得します。ページ上部のQRコードはライブラリ全体、「この動画をスマホで見る」のQRコードは選択中の動画を開きます。
  6. 「YouTubeで元動画を開く」から元の動画へ移動できます。AndroidではYouTubeアプリを指定し、iPhoneでは標準のYouTubeリンクを使用します。端末やブラウザの設定によってはウェブで開きます。移動時は現在の動画を一時停止します。

編集して書き出す

動画シーン設定では、新方式は1シーン、従来形式は表紙＋8枚の9シーンを編集できます。書き出しZIPには素材・字幕・render.shを含み、FFmpegのある環境で実行してMP4を作ります。自動公開動画は静止画＋音声の構成で、編集画面の演出・字幕は自動では適用しません。

05 / PUBLIC & PRIVATE公開と非公開の境界

視聴者が見られる情報

  • 公開した動画のタイトルと再生時間
  • 動画MP4とサムネイルJPEG
  • 一覧、検索、連続再生、共有URL・QRコード
  • 元動画を開くYouTubeリンク

管理者認証が必要な情報

  • 案件の原稿・Drive素材・生成メタデータ
  • 音声キューと実行履歴
  • 生成物の保存・動画公開／非公開の操作

初回だけ必要なR2の有効化

R2未有効の場合、自動処理は「有効化待ち」で待機します。アカウント所有者がCloudflare Dashboardの「Storage & databases → R2 → Overview」で利用条件・料金を確認して契約を有効にすると、次の定期処理からバケット作成・デプロイ・動画公開を自動で進めます。

ここに示しているのは仕組みの説明で、現在の稼働状況を自動取得した表示ではありません。待機・成功・失敗は、サービスログや後述の状態ファイルで確認してください。

公開した動画を取り下げる

公開動画の管理にログインし、「非公開にする」を選びます。一覧と新規配信を止め、定期処理による自動再公開も防ぎます。保存したMP4は保持するため、明示的な再公開で再利用できます。既にダウンロード・再生バッファへ入った内容は回収できません。

R2・Cloudflare・Modal・CLIには、それぞれ契約や利用枠があります。全体が無条件に無料・無制限という構成ではありません。原稿・日本語・画像内容は、公開前に内容を確認してください。

07 / OPERATIONS運用と再試行

以下はPC上で行う管理者向けの操作です。認証情報をコマンド引数や公開ファイルに書く必要はありません。

まず状態を確認する

# 画像と動画公開の次回実行予定
systemctl --user list-timers 'yt-narrator-*'

# 動画公開の直近ログ
journalctl --user -u yt-narrator-videos.service -n 50

# R2待機・自動構築・公開サイクルの状態
cat .artifacts/public-videos/automation.json

必要な処理を1回実行する

# R2確認 → 必要なら構築 → 最大2件を動画公開
npm run automate:videos -- --limit 2

# 指定案件の漫画・図解を生成
npm run generate:visuals -- --project DRIVE_FOLDER_ID

# 動画をPC上に作るだけ。まだ公開しない
npm run publish:videos -- --project DRIVE_FOLDER_ID --render-only

# 明示的に再公開する
npm run publish:videos -- --project DRIVE_FOLDER_ID --republish

生成・保存が失敗しても、検査済みの画像やMP4が残っていれば、再試行で再利用します。入力のハッシュを確認して、生成中に素材が更新された場合は古い内容の保存を拒否します。画像・動画の自動処理は失敗案件を6時間待ち、後続を進めます。

説明書・構成図はこのHTMLに含まれ、外部の図描画ライブラリは不要です。ブラウザの「印刷」からPDFにも保存できます。

08 / FAQよくある質問

音声が何時間も生成されていません。停止ですか？

原稿のある全案件にMP3がそろうと待機します。管理画面の音声待ち件数と実行履歴を確認してください。音声が未完了なら、履歴のエラー、認証休止、Modalの状態を確認します。

PCを止めると、公開動画も見られなくなりますか？

R2に公開済みの動画はCloudflare側から配信されます。PCが必要なのは新しい画像・動画の生成とアップロード、自動セットアップの確認です。

画像を9:16に指定しているのに余白が付くのはなぜですか？

生成サービスが指定どおりの画像比率を返さない場合があります。文字やコマを欠けさせないため、縦横比を保って白い余白で1080×1920pxへ収めます。

タイトル画像が別に作られないのはなぜですか？

新方式では、見出しを含む漫画・インフォグラフィックの1枚をそのままタイトルにも共用する仕様です。別の画像生成は行いません。

表示されているモデルは画像モデルですか？

Codex CLIで構成を考える推論モデルは既定でgpt-6.1-solです。画像モデル名はCLIの結果で取得できないため、推論モデルと区別して「CLIから非公開」と表示します。Antigravity CLIの呼び出し経路もありますが、この環境での画像生成は未検証です。

Cloudflareでの公開が「R2有効化待ち」のままです。

Cloudflareから10042が返っている状態です。DashboardでR2の契約を有効化する必要があります。有効化後はPCの次の定期サイクルでバケット作成・デプロイ・公開が進みます。

画像や動画を保存したのに表示が変わりません。

カタログの更新完了を待ち、必要なら管理画面からカタログ同期を実行してください。Drive画像には最大5分のキャッシュが残る場合があります。公開動画は公開確定の操作が成功するまで一覧へ出ません。

管理者パスワードを忘れたら？

サーバー／PCの管理者が、端末に保存している管理用ファイルと設定を確認してください。パスワードの保管・変更方法はGitHubのREADMEに記載しています。パスワードの値はこのヘルプやGitHubへ掲載しません。

動画を非公開にした後、勝手に再公開されませんか？

非公開フラグを保持するため、定期処理は再公開しません。再公開には案件を指定した明示的な操作が必要です。
